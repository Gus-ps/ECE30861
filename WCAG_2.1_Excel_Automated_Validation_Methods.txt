WCAG 2.1 LEVEL AA: AUTOMATED VALIDATION METHODS FOR EXCEL (.xlsx) FILES
=========================================================================

Derived from: WCAG_2.1_Level_AA_Excel_Requirements.txt (28 relevant criteria)
Compiled: October 16, 2026

PURPOSE
-------
For each WCAG 2.1 Level A/AA criterion that applies to Excel workbooks, this
document says whether a program can check it and how. It also says what still
needs a human reviewer.

The validator only identifies issues and never changes the workbook. Section 8
gives the report format and, for each finding, the message, the input needed
from the user, and the Excel steps to fix it.


==============================================================================
1. SUMMARY
==============================================================================

Automation categories
---------------------
  AUTOMATED: A program can return a reliable PASS/FAIL for most real
             workbooks. A person only needs to review edge cases.
  PARTIAL:   A program can detect missing items and likely failures, and can
             prove some failures outright. Deciding a PASS still needs a
             person (e.g. "is this alt text meaningful?").
  MANUAL:    The criterion depends on running behavior or human judgment that
             a static file scan can't assess. A program can at most tell
             reviewers where to look.

Totals: 28 criteria
  AUTOMATED:  4  (1.4.3, 2.1.4, 2.2.2, 2.5.3)
  PARTIAL:   22
  MANUAL:     2  (2.1.2, 3.3.4)

In practice, a program can do meaningful automated work on 26 of the 28
criteria, but a full PASS without a person is only realistic for about 4.
For the PARTIAL criteria, the program's best role is to reliably catch the
mechanical failures (missing alt text, no table headers, default sheet
names, low contrast, missing error messages) and send everything else to a
human review list.

Suggested result statuses for the validator
-------------------------------------------
  PASS            Check ran and found no issues
  FAIL            Definite violation found (e.g. image with no alt text)
  NEEDS REVIEW    Possible issue, or the criterion needs human judgment
  NOT APPLICABLE  The triggering content doesn't exist (e.g. no images, so
                  2.2.2 and 2.3.1 are N/A; no VBA, so macro checks are N/A)


==============================================================================
2. HOW A PROGRAM CAN READ AN .xlsx FILE
==============================================================================

An .xlsx file is a ZIP archive of XML parts (Office Open XML / ECMA-376).
Everything below can be read without Excel installed.

  Part (inside the ZIP)              Contains
  ---------------------------------  -----------------------------------------
  docProps/core.xml                  Title (dc:title), language (dc:language),
                                     author, subject
  xl/workbook.xml                    Sheet names, sheet order, hidden state,
                                     defined names
  xl/worksheets/sheetN.xml           Cells, merged cells, hyperlinks, data
                                     validation, conditional formatting, sheet
                                     protection, row heights, column widths,
                                     form controls (<controls>)
  xl/sharedStrings.xml               Text values of cells
  xl/styles.xml                      Fonts (size, bold, color), fills, borders,
                                     cell formats, protection (locked),
                                     differential formats (dxf) used by
                                     conditional formatting
  xl/theme/theme1.xml                Theme colors (needed to resolve
                                     "theme=N tint=X" colors)
  xl/tables/tableN.xml               Excel Tables: range, header row, column
                                     names
  xl/drawings/drawingN.xml           Images, shapes, text boxes, chart frames,
                                     with alt text (cNvPr @descr / @title) and
                                     decorative flag
  xl/drawings/vmlDrawingN.vml        Legacy form controls and comment boxes
  xl/ctrlProps/ctrlPropN.xml         Form control type and linked cell
  xl/activeX/activeXN.xml            ActiveX controls
  xl/charts/chartN.xml               Chart type, title, axis titles, series
                                     colors, markers, data labels
  xl/media/*                         Embedded image files (PNG, JPG, GIF...)
  xl/vbaProject.bin                  VBA macros (only in .xlsm/.xlsb/.xltm;
                                     a true .xlsx cannot contain macros)
  [Content_Types].xml / *.rels       Relationships linking all of the above

Suggested tooling (Python examples; equivalents exist in other languages)
  - zipfile + lxml: read any XML part directly. Recommended for drawings,
    charts and controls, which openpyxl does not fully load or preserve.
  - openpyxl: cells, styles, merged cells, tables, data validation,
    conditional formatting, hyperlinks, sheet properties.
  - oletools (olevba): extract VBA source code from vbaProject.bin.
  - Pillow: image dimensions, GIF frame counts and frame durations.
  - pytesseract (Tesseract OCR): detect text inside images.
  - A WCAG contrast function (relative luminance formula, below).
  - Optional: LibreOffice in headless mode to render sheets to PDF/PNG for
    visual checks (clipping, overlap).

Reference point: Excel's built-in Accessibility Checker (Review > Check
Accessibility) covers a subset of these checks: missing alt text, missing
table headers, merged cells, default sheet names, hard-to-read text
contrast, and unclear hyperlink text. Matching its results is a good first
milestone for the validator.

WCAG contrast formula (used by 1.4.3 and 1.4.11)
  For each sRGB channel c (0-1): c' = c/12.92 if c <= 0.04045,
                                 else ((c+0.055)/1.055)^2.4
  Relative luminance L = 0.2126 R' + 0.7152 G' + 0.0722 B'
  Contrast ratio = (L_lighter + 0.05) / (L_darker + 0.05)


==============================================================================
3. CRITERIA THAT ALWAYS APPLY
==============================================================================

------------------------------------------------------------------------------
1.1.1 Non-text Content (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Enumerate every drawing object in xl/drawings/drawingN.xml: pictures
    (xdr:pic), shapes and text boxes (xdr:sp), charts and SmartArt
    (xdr:graphicFrame), and groups (xdr:grpSp). Read the cNvPr element's
    "descr" (alt text) and "title" attributes.
  - Detect objects marked decorative: a:extLst containing an adec:decorative
    element with val="1" (Office 2019+ extension URI
    {C183D7F6-B498-43B3-948B-1728B52AA6E4}).
  - FAIL: object that is not decorative and has an empty or missing descr.
  - NEEDS REVIEW (alt text is probably poor):
      * descr equals the default object name ("Picture 3", "Chart 2",
        "Rectangle 5", "TextBox 1")
      * descr looks like a file name (regex \.(png|jpe?g|gif|bmp|svg)$,
        "IMG_1234", "screenshot")
      * descr is auto-generated ("Description automatically generated",
        "A picture containing...")
      * descr is very short (e.g. fewer than 3 words) or very long (e.g.
        more than 250 characters, which may need a longer description
        elsewhere)
  - Form controls: check the altText attribute on <controlPr> in the sheet
    XML (see 4.1.2).
  - Charts: also check that the chart has a title (see 2.4.6). A chart with
    no alt text but a clear title and adjacent data table still FAILS
    1.1.1. It needs alt text.
MANUAL REVIEW
  - Whether the alt text actually conveys the purpose and content of the
    image or chart (e.g. a chart's alt text should state the key trend or
    point to the source data).
  - Whether objects marked decorative really are decorative.

------------------------------------------------------------------------------
1.3.1 Info and Relationships (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Excel Tables (xl/tables/tableN.xml):
      * FAIL if headerRowCount="0" (table has no header row).
      * NEEDS REVIEW if header names are Excel defaults ("Column1",
        "Column2"...) or blank.
  - Merged cells (<mergeCells> in sheet XML / openpyxl ws.merged_cells):
      * FAIL or NEEDS REVIEW for merges inside a data region or table (they
        break screen reader row/column navigation). Merges used only for a
        title row above the data are lower risk; report them as NEEDS
        REVIEW.
  - Data not marked up as a table: find contiguous blocks of populated
    cells (e.g. 2+ columns x 3+ rows) that are not covered by a table range
    or by a header defined name (TitleRegion*, ColumnTitle*, RowTitle*,
    the naming convention screen readers use to announce headers). Report
    as NEEDS REVIEW: "data range has no programmatic headers".
  - Blank spacer rows/columns: completely empty rows or columns located
    between populated rows/columns inside the used range. NEEDS REVIEW.
  - Split tables: two tables directly adjacent with no empty row/column
    between them. NEEDS REVIEW.
  - Structure shown only by formatting: rows that are bold, larger or
    filled differently (like a header) but sit inside a range that isn't a
    table and has no header defined name. NEEDS REVIEW.
MANUAL REVIEW
  - Whether the header row/column chosen is the correct one.
  - Whether relationships shown visually (indentation, grouping, borders,
    outline levels) are also available in text or structure.

------------------------------------------------------------------------------
1.3.2 Meaningful Sequence (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Content start: report sheets whose first populated cell is far from A1
    (e.g. not in rows 1-3 / columns A-C). NEEDS REVIEW.
  - Hidden content: hidden sheets (state="hidden" / "veryHidden" in
    workbook.xml), hidden rows/columns (hidden="1") that contain data or
    are referenced by visible content. NEEDS REVIEW. Screen readers and
    sighted users get different content.
  - Floating objects: drawing objects (text boxes, shapes, images) whose
    anchor range overlaps populated cells, or text boxes containing
    instructions. Screen readers don't reach these in cell order. NEEDS
    REVIEW.
  - Text-box-only content: sheets where meaningful text exists only in
    shapes/text boxes and not in cells. NEEDS REVIEW.
  - Sheet order: report the sheet sequence from workbook.xml (e.g.
    "Instructions" or "README" sheets that aren't first). NEEDS REVIEW.
MANUAL REVIEW
  - Whether reading cells left-to-right, top-to-bottom (and sheets in tab
    order) gives a sequence that makes sense.

------------------------------------------------------------------------------
1.3.3 Sensory Characteristics (Level A): PARTIAL (low automation)
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Search all text (cell values, comments/notes, text boxes, data
    validation prompts, chart titles) for sensory-only references, e.g.:
      color words near cell/field terms: "(red|green|blue|yellow|orange|
        grey|gray|shaded|highlighted|colored) (cell|cells|row|rows|column|
        box|field|area|text)"
      position words: "on the (left|right)", "above", "below", "to the
        right", "box on the", "top-right", "the arrow"
      shape words: "(round|square|circle|triangle) (button|icon|shape)"
  - Report matches as NEEDS REVIEW with the sheet/cell location.
MANUAL REVIEW
  - Whether a match actually relies only on the sensory property, or also
    names the cell/label (e.g. "the yellow Total column (column F)" passes).

------------------------------------------------------------------------------
1.4.1 Use of Color (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Conditional formatting (<conditionalFormatting> in sheet XML + dxf in
    styles.xml): report rules whose only effect is a fill or font color
    change (no icon set, no number format change, no bold/italic/
    underline, and no text change). NEEDS REVIEW: "meaning may rely on
    color alone".
    Rules of type iconSet pass more easily if the icons differ in shape;
    data bars and color scales are color/length based, so report them as
    NEEDS REVIEW.
  - Manual fill colors: within a single column of a data region, detect
    cells whose fill or font color differs from the rest while their text
    gives no matching marker (e.g. no status column, no symbol). NEEDS
    REVIEW.
  - Charts (xl/charts/chartN.xml):
      * Line/scatter charts with 2+ series where every series uses the same
        marker symbol (or c:marker/c:symbol val="none") and the same dash
        style, with no data labels. NEEDS REVIEW: series are
        distinguished by color only.
      * Pie/doughnut charts without data labels showing the category name
        (c:dLbls/c:showCatName) and no legend. NEEDS REVIEW.
      * Bar/column charts with multiple series and no data labels or
        pattern fills. NEEDS REVIEW.
  - Hyperlinks styled only by color (no underline in the font). NEEDS
    REVIEW.
MANUAL REVIEW
  - Whether the color is actually conveying information, and whether an
    equivalent non-color cue exists nearby (a legend in text, a status
    column, a note).

------------------------------------------------------------------------------
1.4.3 Contrast (Minimum) (Level AA): AUTOMATED
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - For every non-empty cell, resolve its effective style from cellXfs in
    styles.xml:
      * Font color: rgb="FFRRGGBB", theme="N" (+ tint) resolved via
        theme1.xml, indexed="N" via the default indexed palette (or
        <indexedColors> override), auto="1" treated as black (system
        window text).
      * Fill color: patternFill fgColor for solid fills. No fill = white
        (default background). Gradient fills: test against each gradient
        stop and use the worst case. Patterned fills: NEEDS REVIEW.
      * Apply theme tint to the HSL lightness L (0-1) of the base theme
        color: if tint < 0, L' = L * (1 + tint); if tint > 0,
        L' = L * (1 - tint) + tint.
  - Compute contrast ratio. Thresholds:
      * Large text (font size >= 18pt, or >= 14pt and bold): 3:1
      * All other text: 4.5:1
  - FAIL if below threshold.
  - Conditional formatting: for each rule's dxf, also test the font/fill
    combination it produces (merge the dxf over the base style). You can
    evaluate whether the rule actually triggers, but the simpler and safer
    method is to test every possible combination and report failures.
  - Text in shapes, text boxes, charts (titles, labels, legends, axis
    text): read a:solidFill in run properties (a:rPr) and the shape fill
    (a:spPr) in drawing and chart XML; test the same thresholds.
  - Rich text runs inside a cell (sharedStrings <r><rPr>) can have their own
    colors. Test each run.
EXCEPTIONS / REVIEW
  - Exempt: logos, inactive controls, text that is decorative or part of a
    picture. These can't always be recognized automatically.
  - Text with the same color as its background (contrast ratio ~1:1) is
    usually "hidden" text. Report it as NEEDS REVIEW rather than ignoring
    it, since hidden text is read by screen readers.
  - Cells over a sheet background image (<picture> element in sheet XML)
    can't be measured reliably. NEEDS REVIEW.

------------------------------------------------------------------------------
1.4.4 Resize Text (Level AA): PARTIAL (low automation)
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Excel zoom scales cells and text together, so clipping usually comes
    from content that was already clipped. Detect:
      * Rows with customHeight="1" containing wrapped text (wrapText="1")
        whose estimated line count x line height exceeds the row height.
        NEEDS REVIEW: text may be cut off.
      * Cells whose estimated text width exceeds the column width while the
        cell to the right is non-empty (text is truncated on screen) and
        wrapText/shrinkToFit are off. NEEDS REVIEW.
      * shrinkToFit="1": text is rendered smaller than its font size.
        NEEDS REVIEW.
      * Very small fonts (e.g. < 9pt) in cells, shapes or charts. NEEDS
        REVIEW (not a WCAG failure by itself, but often related).
      * Text boxes/shapes whose text (estimated from font metrics) is
        larger than the shape and where autofit (a:spAutoFit /
        a:normAutofit) is off. NEEDS REVIEW.
  - Optional: render the workbook with LibreOffice headless at 100% and
    200% scale and compare for overlapping or clipped text.
MANUAL REVIEW
  - Zoom the workbook to 200% and confirm no content or function is lost.

------------------------------------------------------------------------------
1.4.5 Images of Text (Level AA): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Run OCR (e.g. Tesseract) on every image in xl/media that is referenced
    by a drawing (skip images marked decorative only if you also report
    them for review).
  - NEEDS REVIEW if OCR finds substantial text (e.g. > 10 words, or text
    covering a large share of the image area). Especially flag images that
    look like tables or screenshots (many text lines in a grid).
  - Also flag a sheet background image (<picture> element) containing text.
MANUAL REVIEW
  - Whether the image is a logo/brand (exempt) or whether a particular
    presentation is essential. Otherwise the text should be real cell text.

------------------------------------------------------------------------------
1.4.11 Non-text Contrast (Level AA): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Charts (xl/charts/chartN.xml): for each series, resolve its fill/line
    color (c:ser/c:spPr; for default colors, derive from the chart style and
    theme accent colors). Compare each with the plot-area and chart-area
    background (c:plotArea/c:spPr, c:chartSpace/c:spPr; default white):
      * FAIL if < 3:1 against the background and the series has no
        visible outline or data labels that carry the information.
    For pie/doughnut/stacked charts, also compare adjacent slices/segments.
    If two adjacent segments are < 3:1 with no separating border of
    sufficient contrast, report NEEDS REVIEW.
  - Gridlines/axes needed to read values: compare their line color with the
    background. NEEDS REVIEW below 3:1.
  - Shapes used as icons or indicators (xdr:sp with a fill, no text):
    compare fill/outline with the cell background behind them. NEEDS
    REVIEW below 3:1.
  - Conditional formatting icon sets and data bars: Excel's default colors
    are fixed. Report custom colors below 3:1 vs. the cell fill.
  - Cell borders that carry meaning (e.g. outlining input cells): compare
    border color with the fill. NEEDS REVIEW below 3:1.
MANUAL REVIEW
  - Whether the graphic is required to understand the content (decorative
    graphics are exempt), and whether information is still available
    another way (data labels, adjacent table).
  - Form control appearance is drawn by Excel and is generally exempt
    (user agent appearance, not modified by the author).

------------------------------------------------------------------------------
2.4.2 Page Titled (Level A): PARTIAL (high automation)
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - docProps/core.xml: FAIL if dc:title is missing or empty.
  - NEEDS REVIEW if the title equals the file name, or is a generic value
    ("Book1", "Workbook", "Untitled", "Document").
  - xl/workbook.xml sheet names:
      * FAIL (or NEEDS REVIEW) for default names matching ^Sheet\d+$ (and
        localized equivalents, e.g. ^Feuil\d+$, ^Tabelle\d+$, ^Hoja\d+$).
      * FAIL for visible sheets with no content (no cells, no drawings,
        no charts). Blank sheets confuse screen reader users.
      * NEEDS REVIEW for duplicate-looking names ("Data", "Data (2)") or
        very short names (1-2 characters).
MANUAL REVIEW
  - Whether the title and sheet names actually describe the topic or
    purpose.

------------------------------------------------------------------------------
2.4.3 Focus Order (Level A): PARTIAL (low automation)
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Cell navigation order is fixed by Excel (row/column order), so the
    file-level risks are the same as 1.3.2: content far from A1, floating
    objects, and hidden content. Reuse those results.
  - Form controls/shapes: list them in drawing (z-) order, which is the
    order Excel uses when cycling through objects. Compare against their
    on-sheet position (top-to-bottom, left-to-right by anchor). NEEDS
    REVIEW if the orders differ.
  - VBA UserForms: in the extracted VBA/form data, read each control's
    TabIndex and compare to its Top/Left position. NEEDS REVIEW if the
    sequence jumps around.
  - Protected sheets that allow selecting unlocked cells only
    (<sheetProtection selectLockedCells="1">): list the unlocked-cell
    sequence for review, since Tab moves between them in order.
MANUAL REVIEW
  - Tab/arrow through the workbook and confirm the order preserves meaning.

------------------------------------------------------------------------------
2.4.4 Link Purpose (In Context) (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Collect hyperlinks: <hyperlinks> in sheet XML (r:id -> external target
    in sheet rels, or "location" for internal links), HYPERLINK() formulas,
    and hyperlinks on shapes/images (a:hlinkClick in drawing XML).
  - The link text is the cell's displayed value (or the "display"
    attribute / the HYPERLINK() second argument); for shapes, the shape's
    text or alt text.
  - FAIL: empty link text; image/shape link with no alt text.
  - NEEDS REVIEW:
      * Link text is a raw URL (^https?://, ^www\.) or email address.
      * Generic text: "click here", "here", "link", "more", "read more",
        "this", "details", "info".
      * Same link text pointing to different targets, or different text
        for the same target.
  - Optional: the tooltip attribute (ScreenTip) can be reported as extra
    context.
MANUAL REVIEW
  - Whether the link text plus its context (same row, column header)
    makes the destination clear.

------------------------------------------------------------------------------
2.4.6 Headings and Labels (Level AA): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Tables: FAIL for blank header cells; NEEDS REVIEW for default
    ("Column1"), duplicate, or very short (1 character) header names.
  - Charts: FAIL if there's no chart title (no c:title, or
    c:autoTitleDeleted val="1"). NEEDS REVIEW if a value/category axis
    has no c:title (except pie/doughnut charts, which have no axes).
  - Sheet names: reuse 2.4.2 results.
  - Input cells (see 3.3.2): flag input cells with no adjacent label.
MANUAL REVIEW
  - Whether headers, titles and labels clearly describe their content.

------------------------------------------------------------------------------
3.1.1 Language of Page (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Read dc:language in docProps/core.xml.
      * Excel does not always write this property. If it's missing, report
        NEEDS REVIEW (or FAIL, if your organization's policy requires the
        property to be set).
      * If present, validate it's a well-formed BCP 47 tag (e.g. en-US).
  - Optional: run language detection (e.g. langdetect/fastText) on the
    workbook's text and compare with dc:language. NEEDS REVIEW if they
    differ.
MANUAL REVIEW / LIMITATION
  - In practice, screen readers often use the Office editing language
    rather than a file property, so confirming the language is announced
    correctly may need a screen reader test.
  - Decide in advance what your validator will treat as the authoritative
    "language of page" for .xlsx, and document it.


==============================================================================
4. CRITERIA THAT APPLY ONLY WITH CONTROLS, BUTTONS OR VBA MACROS
==============================================================================

DETECTION (determines APPLICABLE vs NOT APPLICABLE)
  - VBA: xl/vbaProject.bin exists (only possible in .xlsm/.xlsb/.xltm).
    Extract source with olevba. A file with an .xlsx extension that
    contains macros is malformed; report it.
  - Legacy form controls: <controls> elements in sheet XML, with
    xl/ctrlProps/ctrlPropN.xml giving objectType (Button, CheckBox, Drop,
    List, Radio, Spin, Scroll, GBox, Label, EditBox).
  - ActiveX controls: xl/activeX/activeXN.xml (classid identifies type).
  - Macro-assigned shapes/images: "macro" attribute on xdr:sp / xdr:pic in
    drawing XML.
  - In-cell check boxes (Microsoft 365): boolean cells with the
    check box cell format. These are keyboard accessible and generally pass
    2.1.1.
  If none of these exist, every criterion in this section is NOT
  APPLICABLE.

------------------------------------------------------------------------------
2.1.1 Keyboard (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Legacy form controls, ActiveX controls and macro-assigned shapes
    generally can't be reached and operated by keyboard alone in Excel.
    For each one, report NEEDS REVIEW (or FAIL under a strict policy)
    unless the same function is also available by keyboard. Look for:
      * a keyboard shortcut for the macro (Application.OnKey with modifier
        keys, or a macro shortcut set in the VBA attribute
        "Attribute <Name>.VB_ProcData.VB_Invoke_Func = "x\n14"").
      * a cell-based alternative (e.g. a data validation list instead of a
        dropdown control).
  - VBA event code relying on mouse-only events (BeforeDoubleClick,
    BeforeRightClick, MouseDown/MouseMove on UserForm controls) with no
    keyboard equivalent (KeyDown/KeyPress or a command). NEEDS REVIEW.
MANUAL REVIEW
  - Operate every control and macro with the keyboard only.

------------------------------------------------------------------------------
2.1.2 No Keyboard Trap (Level A): MANUAL
------------------------------------------------------------------------------
AUTOMATED CHECKS (pointers only)
  - Report UserForms (form designer modules in the VBA project) and
    modeless dialogs as items to test.
  - Report VBA that cancels navigation or keeps re-selecting a cell
    (SelectionChange handlers that call .Select / .Activate back to the
    same range; Application.OnKey "{TAB}" / "{ESC}" being disabled with
    OnKey "<key>", ""). NEEDS REVIEW.
MANUAL REVIEW
  - Open each UserForm/control with the keyboard and confirm Tab, Esc or a
    Close button lets focus leave. Requires running the workbook.

------------------------------------------------------------------------------
2.1.4 Character Key Shortcuts (Level A): AUTOMATED
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Parse VBA for Application.OnKey "<key>", "<macro>" calls.
  - In OnKey syntax, ^ = Ctrl, % = Alt, + = Shift. FAIL if the key string
    is a single printable character (letter, digit, punctuation or symbol)
    with no ^ or % modifier (Shift alone (+) still counts as a character
    key), unless the code also offers a way to turn it off (e.g. a
    matching OnKey "<key>" reset tied to a user option). In that case,
    report NEEDS REVIEW.
  - Keys in braces ({F5}, {ENTER}) are non-printable keys and pass.
  - Shortcuts assigned through the Macro Options dialog always need Ctrl,
    so they pass.
MANUAL REVIEW
  - Only if a turn-off/remap mechanism exists that the parser can't
    recognize.

------------------------------------------------------------------------------
2.2.1 Timing Adjustable (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Search VBA for timing constructs: Application.OnTime, Application.Wait,
    Timer-based loops (Do While Timer < ...), Sleep API declarations, and
    auto-close logic (ThisWorkbook.Close / Application.Quit inside
    OnTime-scheduled procedures).
  - Report each as NEEDS REVIEW with the procedure name.
  - PASS (N/A) if no timing constructs exist.
MANUAL REVIEW
  - Whether the time limit can be turned off, adjusted 10x, or extended,
    or whether an exception (real-time, essential, > 20 hours) applies.

------------------------------------------------------------------------------
2.5.3 Label in Name (Level A): AUTOMATED
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - For each control with visible text:
      * Visible label: the button/check box caption (VML x:ClientData
        text, the text body of the control in vmlDrawing, ActiveX
        Caption property), or the text of a macro-assigned shape.
      * Accessible name: the altText attribute on <controlPr> (or the
        shape's cNvPr descr). If no alt text is set, Excel uses the
        caption, which passes.
  - Normalize both (lowercase, collapse whitespace, strip punctuation and
    accelerator "&"). FAIL if the accessible name does not contain the
    visible label. NEEDS REVIEW if it contains the label but not at the
    start (best practice).
MANUAL REVIEW
  - Labels that are images of text (OCR them, or review by hand).

------------------------------------------------------------------------------
3.2.1 On Focus (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Parse VBA for Worksheet_SelectionChange, Workbook_SheetSelectionChange,
    Worksheet_Activate, Workbook_SheetActivate, and control
    Enter/GotFocus events.
  - Inside those handlers, report context-changing calls: .Activate /
    .Select on another sheet or workbook, Application.Goto,
    UserForm.Show, MsgBox, Workbooks.Open, FollowHyperlink, window
    changes. NEEDS REVIEW (most are real failures, but whether the
    target is a "change of context" needs a person).
MANUAL REVIEW
  - Move focus through cells and controls and confirm nothing jumps,
    opens or switches unexpectedly.

------------------------------------------------------------------------------
3.2.2 On Input (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Parse VBA for Worksheet_Change, Workbook_SheetChange, control
    Change/Click events, and form control macros (onAction / macro
    attribute on dropdowns, check boxes, option buttons).
  - Inside those handlers, report the same context-changing calls as 3.2.1.
    NEEDS REVIEW.
  - Search sheet text near the control/cell for a warning (e.g. "selecting
    ... will open", "will take you to"). If found, lower the severity.
MANUAL REVIEW
  - Change values and confirm any context change was announced beforehand.

------------------------------------------------------------------------------
4.1.2 Name, Role, Value (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Name: FAIL if a form control/ActiveX control has no alt text and no
    caption (e.g. dropdowns, list boxes, spinners and scroll bars have no
    caption, so they need altText).
  - Role: report controls by type. Built-in form controls expose a known
    role. ActiveX and custom shape-based "controls" (shapes acting as
    buttons or check boxes) don't expose a meaningful role. NEEDS REVIEW
    or FAIL (strict).
  - Value/state: check box/option button/dropdown should have a linked cell
    (fmlaLink in ctrlProps) so the state is also available in a cell.
    NEEDS REVIEW if missing.
MANUAL REVIEW
  - Screen reader test that each control announces its name, role and
    state, and that changes are announced.


==============================================================================
5. CRITERIA THAT APPLY ONLY TO DATA-ENTRY WORKBOOKS
==============================================================================

DETECTION (determines APPLICABLE vs NOT APPLICABLE)
  Treat the workbook as collecting input if any of these is true:
  - Sheet protection is on (<sheetProtection sheet="1">) and some cells are
    unlocked (cellXfs <protection locked="0">). Unlocked cells are input
    cells.
  - <dataValidations> exist on the sheet.
  - Form controls or in-cell check boxes are linked to cells.
  - Text such as "enter", "fill in", "required", "complete this form".
  Otherwise these criteria are NOT APPLICABLE.

------------------------------------------------------------------------------
3.3.1 Error Identification (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - For each <dataValidation> (type other than "none"):
      * FAIL if showErrorMessage is not "1". Invalid input is silently
        accepted or not explained.
      * NEEDS REVIEW if showErrorMessage="1" but error is empty (Excel
        shows a generic "This value doesn't match the data validation
        restrictions" message that doesn't identify the field or
        describe the problem).
      * NEEDS REVIEW if errorStyle is "warning" or "information" (the
        error can be bypassed; acceptable, but confirm).
  - Conditional formatting used to show errors (e.g. red fill when invalid)
    with no text message: NEEDS REVIEW (also a 1.4.1 issue).
  - VBA validation (Worksheet_Change with MsgBox): report for review.
MANUAL REVIEW
  - Whether the error message names the field in error and describes the
    problem in text.

------------------------------------------------------------------------------
3.3.2 Labels or Instructions (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - For each input cell (unlocked cell on a protected sheet, or a cell
    with data validation):
      * Look for a text label in the cell directly to the left or above
        (or the table header for that column).
      * FAIL if no adjacent label exists.
  - Data validation input messages: report showInputMessage="1" with
    prompt text as supporting instructions. NEEDS REVIEW if format-
    restricted cells (date, decimal, textLength, list) have no prompt and
    no visible instruction nearby.
  - Instructions that exist only in comments/notes (hover-only): NEEDS
    REVIEW.
  - Required fields: if text like "*" or "required" is used, check that
    the meaning of "*" is explained somewhere in text.
MANUAL REVIEW
  - Whether labels and instructions are clear and sufficient.

------------------------------------------------------------------------------
3.3.3 Error Suggestion (Level AA): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Builds on 3.3.1. For validations of type list, whole, decimal, date,
    time or textLength, the allowed values are known from formula1/
    formula2 and the operator. Check the error text mentions the
    expectation, e.g.:
      * list: mentions choosing from a list, or names the options
      * whole/decimal/date: contains a number, date or the words
        "between", "greater", "less", "format"
      * textLength: contains a number or "characters"
    NEEDS REVIEW if no such hint is found.
  - Validation type "custom" (formula-based): NEEDS REVIEW.
MANUAL REVIEW
  - Whether the suggestion actually helps the user fix the error, and
    whether a suggestion would compromise security (exempt).

------------------------------------------------------------------------------
3.3.4 Error Prevention (Legal, Financial, Data) (Level AA): MANUAL
------------------------------------------------------------------------------
AUTOMATED CHECKS (pointers only)
  - Report workbooks containing keywords suggesting legal/financial/test
    submissions ("signature", "agreement", "I certify", "payment",
    "invoice", "amount due", "account", "quiz", "score", "submit").
  - Report VBA that submits, sends or deletes data (e.g. .SendMail,
    Outlook automation, XMLHTTP/WinHttp POST, database connections
    (ADODB) with INSERT/UPDATE/DELETE, Kill, .Delete on sheets/ranges).
    If there's no confirmation (MsgBox with vbYesNo/vbOKCancel) in the
    same procedure, raise severity.
MANUAL REVIEW
  - Decide whether the workbook causes legal commitments, financial
    transactions, data changes or test submissions, and if so confirm
    it's reversible, checked, or has a review/confirm step.


==============================================================================
6. CRITERIA THAT APPLY ONLY WITH ANIMATED IMAGES
==============================================================================

DETECTION
  - For each image in xl/media referenced by a drawing, open it with
    Pillow. Animated if format is GIF (or APNG/WebP) with n_frames > 1.
  - If none are animated, both criteria are NOT APPLICABLE.

------------------------------------------------------------------------------
2.2.2 Pause, Stop, Hide (Level A): AUTOMATED
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - Total animation time = sum of frame durations (info["duration"] per
    frame) x loop count (info["loop"], where 0 = infinite).
  - FAIL if it runs longer than 5 seconds (or loops forever) and plays
    automatically. The workbook can't provide its own pause control.
    Excel's app-level setting (turning off automatic GIF playback in
    accessibility settings) is a user preference, not something the
    content provides; decide whether your policy accepts it, and document
    it.
  - PASS if total duration <= 5 seconds.
MANUAL REVIEW
  - Whether the animation is essential (rare).

------------------------------------------------------------------------------
2.3.1 Three Flashes or Below Threshold (Level A): PARTIAL
------------------------------------------------------------------------------
AUTOMATED CHECKS
  - For each animated image, step through frames with their durations and
    compute per-frame relative luminance (and red saturation) over the
    image area.
  - Count transitions: a "flash" is a pair of opposing luminance changes of
    >= 10% of the maximum relative luminance where the darker state is
    below 0.80. Red flash is a transition to/from saturated red
    (R/(R+G+B) >= 0.8).
  - FAIL if more than 3 flashes occur in any 1-second window over an area
    large enough to matter (the general threshold is about 25% of a 10
    degree visual field, roughly 341 x 256 px at 1024 x 768 viewing).
    Images smaller than that area pass the threshold.
  - Simpler safe check: PASS if the GIF frame rate can't produce more than
    3 changes per second (all frame durations >= 333 ms), or if the image
    is smaller than the threshold area.
MANUAL REVIEW
  - Borderline cases. Dedicated flash analysis tools (e.g. the Trace
    Center's PEAT, or Harding FPA) give a more authoritative result.


==============================================================================
7. RECOMMENDED VALIDATOR STRUCTURE
==============================================================================

  1. Open the ZIP, build an index of parts and relationships.
  2. Run detection: VBA? controls? input cells? animated images? This sets
     NOT APPLICABLE for whole groups of criteria.
  3. Run the AUTOMATED checks (1.4.3, 2.1.4, 2.2.2, 2.5.3) and report
     PASS/FAIL.
  4. Run the PARTIAL checks and report FAIL for definite violations and
     NEEDS REVIEW items with exact locations (sheet, cell, object name).
  5. Generate a manual review checklist covering:
       - every NEEDS REVIEW item
       - the MANUAL criteria (2.1.2, 3.3.4) when applicable
       - judgment questions that always need a person (alt text quality,
         label/title clarity, reading order, color-only meaning)
  6. Report overall conformance as:
       "Does not conform": any FAIL
       "Conformance pending manual review": no FAIL, some NEEDS REVIEW
       "Conforms (automated checks)": only PASS / NOT APPLICABLE. Even
         then, judgment-based criteria should be signed off by a person
         before claiming full WCAG 2.1 AA conformance.
  7. Produce the findings report described in Section 8.


==============================================================================
8. REPORTING FINDINGS
==============================================================================

The validator only identifies issues. It never modifies the workbook. Each
finding should give the user everything needed to fix the issue in Excel or
to supply the input the fix requires.

------------------------------------------------------------------------------
8.1 Reporting principles
------------------------------------------------------------------------------
  - READ-ONLY: Open the file read-only and never save it. Libraries such as
    openpyxl can silently drop charts, images, form controls, comments and
    macros when they save a workbook. If the program ever creates a copy
    (e.g. to render it), write the copy to a temporary location and delete
    it afterwards.
  - FLAG GENEROUSLY: A person reviews every finding, so a false positive
    costs a quick dismissal, while a missed issue may never get fixed. For
    PARTIAL checks, set thresholds on the cautious side.
  - ONE FINDING PER ISSUE PER LOCATION: e.g. 3 images without alt text = 3
    findings, so each can be fixed and closed separately. Group them in the
    report for readability.
  - ACTIONABLE: Every finding names the exact location, says what was found
    (with measured values where available), and says what the user must do
    or decide.
  - SUGGEST, DON'T DECIDE: The program may offer a suggested value (e.g. a
    compliant color, a sheet name based on the sheet's first header), but
    it should be labeled as a suggestion. The user chooses.
  - STABLE IDs: Give each finding type a fixed rule ID (Section 8.6) so
    results can be compared between runs and users can mark specific
    findings as "accepted / not an issue".

------------------------------------------------------------------------------
8.2 Finding record fields
------------------------------------------------------------------------------
  Field            Required  Description
  ---------------  --------  -------------------------------------------------
  finding_id       Yes       Unique ID within this report (e.g. F-0007)
  rule_id          Yes       Stable rule ID from Section 8.6 (e.g.
                             1.1.1-ALT-MISSING)
  criterion        Yes       WCAG number and name (e.g. "1.1.1 Non-text
                             Content")
  level            Yes       A or AA
  status           Yes       FAIL or NEEDS REVIEW (PASS / NOT APPLICABLE are
                             reported per criterion, not as findings)
  severity         Yes       Critical, Serious, Moderate or Minor (8.3)
  location         Yes       Sheet name plus one of: cell/range ("B4:F20"),
                             object name ("Picture 3"), chart name ("Chart 2,
                             series 'Revenue'"), control name, VBA module and
                             procedure, or "Workbook" for file-level items
  found            Yes       What was detected, with measured values (e.g.
                             "Contrast 2.8:1 (font #999999 on fill #FFFFFF,
                             11pt). Required: 4.5:1.")
  why_it_matters   Yes       One sentence on the user impact
  action           Yes       What the user needs to do or decide
  input_type       Yes       The kind of response needed (8.4)
  suggested_value  No        Program's suggestion (e.g. "#767676" or
                             "Sales by Region")
  how_to_fix       Yes       Excel steps (menu path) to make the fix
  evidence         No        Raw data for developers (XML part path, element,
                             attribute values)
  user_response    No        Filled in by the user: the value supplied, or
                             Fixed / Not an issue (with reason) / Deferred

------------------------------------------------------------------------------
8.3 Severity levels
------------------------------------------------------------------------------
  Critical  Blocks access to content or function for some users. (e.g.
            control not usable by keyboard, chart with no alt text and no
            data table, flashing content)
  Serious   Makes content very hard to use. (e.g. data table with no headers,
            text contrast below 3:1, error message missing)
  Moderate  Causes confusion or extra effort. (e.g. default sheet names,
            generic link text, merged cells in a title row)
  Minor     Best practice or likely-acceptable item to confirm. (e.g. label
            not at the start of the accessible name, missing axis title
            when the chart title explains it)

  Every FAIL should be Critical or Serious, unless the rule says otherwise.
  NEEDS REVIEW items can be any level.

------------------------------------------------------------------------------
8.4 User input types
------------------------------------------------------------------------------
  TEXT        User types a value (alt text, title, sheet name, link text,
              error message).
  CHOICE      User picks from options (e.g. "Add alt text" / "Mark as
              decorative" / "Not an issue").
  CONFIRM     User confirms or dismisses a possible issue (yes, it's a
              problem / no, it's fine).
  EDIT        User must change formatting, structure or code in Excel (no
              single value can be supplied).
  MANUAL TEST User must perform a test (keyboard, screen reader, zoom) and
              record the result.

------------------------------------------------------------------------------
8.5 Report layout
------------------------------------------------------------------------------
  Use the same content in both a human-readable report and a machine-
  readable file (JSON or CSV), so results can be tracked or imported.

  Human-readable report:

    WCAG 2.1 AA ACCESSIBILITY REPORT
    File:        Q3_Budget.xlsx
    Checked:     2026-10-16 14:32
    Validator:   <name> v1.0
    Result:      DOES NOT CONFORM (12 failures, 9 items need review)

    SUMMARY BY CRITERION
      Criterion                         Status          Fail  Review
      1.1.1 Non-text Content            FAIL               3       1
      1.3.1 Info and Relationships      FAIL               1       2
      1.4.3 Contrast (Minimum)          FAIL               6       0
      2.4.2 Page Titled                 FAIL               2       0
      2.1.1 Keyboard                    NOT APPLICABLE     -       -
      ...

    FINDINGS (sorted by severity, then sheet, then location)

    [F-0001] FAIL | Serious | 1.1.1 Non-text Content (A)
      Location:  Sheet "Summary", Picture 3 (anchored at D2)
      Found:     Image has no alt text and isn't marked as decorative.
      Why:       Screen reader users get no information about this image.
      Action:    Enter alt text describing the image, or mark it as
                 decorative if it adds no information.
      Input:     CHOICE + TEXT
      Fix:       Right-click the image > View Alt Text > type a description,
                 or check "Mark as decorative".

    [F-0002] FAIL | Serious | 1.4.3 Contrast (Minimum) (AA)
      Location:  Sheet "Summary", B4:F4
      Found:     Contrast 2.8:1 (font #999999 on fill #FFFFFF, 11pt
                 regular). Required: 4.5:1.
      Action:    Change the font or fill color.
      Input:     EDIT
      Suggested: Font #767676 (4.5:1) or darker
      Fix:       Select the cells > Home > Font Color / Fill Color.

    MANUAL REVIEW CHECKLIST
      [ ] 2.1.2 Open UserForm "frmEntry" and confirm Tab/Esc can leave it.
      [ ] 1.3.2 Read sheet "Summary" in cell order and confirm it makes
          sense.
      ...

  Machine-readable record (JSON example):

    {
      "finding_id": "F-0002",
      "rule_id": "1.4.3-TEXT-CONTRAST",
      "criterion": "1.4.3 Contrast (Minimum)",
      "level": "AA",
      "status": "FAIL",
      "severity": "Serious",
      "location": {"sheet": "Summary", "range": "B4:F4"},
      "found": "Contrast 2.8:1 (font #999999 on fill #FFFFFF, 11pt regular). Required: 4.5:1.",
      "why_it_matters": "Low-vision users may not be able to read this text.",
      "action": "Change the font or fill color so contrast is at least 4.5:1.",
      "input_type": "EDIT",
      "suggested_value": {"font_color": "#767676"},
      "how_to_fix": "Select the cells > Home > Font Color / Fill Color.",
      "evidence": {"part": "xl/styles.xml", "cellXfs_index": 14},
      "user_response": null
    }

  Group adjacent cells with the same issue and style into one range (e.g.
  B4:F4) to keep the report short.

------------------------------------------------------------------------------
8.6 Rules, messages and fixes by criterion
------------------------------------------------------------------------------
  Format for each rule:
    RULE-ID  [default status / severity]
      Found:   message template ({braces} = values filled in by the program)
      Action:  what the user must do or decide       Input: input type
      Fix:     Excel steps
  Excel menu paths are for Microsoft 365 / Excel 2021 on Windows; labels
  may differ slightly on Mac or older versions.

  ===== 1.1.1 Non-text Content (A) =====

  1.1.1-ALT-MISSING  [FAIL / Serious; Critical for charts]
    Found:   {object type} "{name}" has no alt text and isn't marked as
             decorative.
    Action:  Write alt text that conveys the object's purpose, or mark it
             decorative.                          Input: CHOICE + TEXT
    Fix:     Right-click the object > View Alt Text > type a description, or
             check "Mark as decorative".
  1.1.1-ALT-POOR  [NEEDS REVIEW / Moderate]
    Found:   Alt text for "{name}" may not be meaningful: "{alt text}"
             ({reason: default name / file name / auto-generated / too
             short / too long}).
    Action:  Confirm the alt text describes the content, or replace it.
                                                  Input: CONFIRM or TEXT
    Fix:     Right-click > View Alt Text > edit the description.
  1.1.1-CHART-ALT  [FAIL / Critical]
    Found:   Chart "{name}" has no alt text.
    Action:  Write alt text summarizing what the chart shows (type, data,
             key trend), and say where the source data is.  Input: TEXT
    Fix:     Right-click the chart border > View Alt Text.
  1.1.1-DECORATIVE-CHECK  [NEEDS REVIEW / Minor]
    Found:   "{name}" is marked as decorative.
    Action:  Confirm it adds no information.      Input: CONFIRM
    Fix:     If not decorative: View Alt Text > uncheck "Mark as decorative"
             > add a description.

  ===== 1.3.1 Info and Relationships (A) =====

  1.3.1-TABLE-NO-HEADER  [FAIL / Serious]
    Found:   Table "{table name}" ({range}) has no header row.
    Action:  Turn on the header row and give each column a name.
                                                  Input: EDIT + TEXT
    Fix:     Click in the table > Table Design > check "Header Row", then
             type the column names.
  1.3.1-DATA-NOT-TABLE  [NEEDS REVIEW / Serious]
    Found:   Data range {range} on "{sheet}" isn't formatted as a table and
             has no defined header names.
    Action:  Convert it to a table with headers (or confirm it isn't
             tabular data).                       Input: CONFIRM or EDIT
    Fix:     Select the range > Insert > Table > check "My table has
             headers". (Alternative: define a name starting with
             "ColumnTitle" for the header cell.)
  1.3.1-MERGED-CELLS  [FAIL / Serious in data; NEEDS REVIEW / Moderate in
                      title rows]
    Found:   Merged cells at {range} on "{sheet}".
    Action:  Unmerge the cells; to keep the visual layout, use Center Across
             Selection.                           Input: EDIT
    Fix:     Select > Home > Merge & Center > Unmerge Cells; then Format
             Cells (Ctrl+1) > Alignment > Horizontal > Center Across
             Selection.
  1.3.1-BLANK-SPACER  [NEEDS REVIEW / Moderate]
    Found:   Empty {row/column} {number} inside the data on "{sheet}"
             appears to be used for spacing.
    Action:  Delete the empty row/column and use row height or column
             width for spacing.                   Input: CONFIRM + EDIT
    Fix:     Right-click the row/column header > Delete; adjust height or
             width with Home > Format.
  1.3.1-FORMAT-ONLY-HEADER  [NEEDS REVIEW / Moderate]
    Found:   Row {n} on "{sheet}" is styled like a header but isn't a
             table header.
    Action:  Make it a real header row (see 1.3.1-DATA-NOT-TABLE).
                                                  Input: CONFIRM + EDIT
    Fix:     Insert > Table with "My table has headers" checked.

  ===== 1.3.2 Meaningful Sequence (A) =====

  1.3.2-START-NOT-A1  [NEEDS REVIEW / Minor]
    Found:   Content on "{sheet}" starts at {cell}, not near A1.
    Action:  Move content to start at A1, or add a note in A1 saying where
             content begins.                      Input: CONFIRM + EDIT
    Fix:     Select the content > Cut (Ctrl+X) > click A1 > Paste; or
             type a note in A1.
  1.3.2-HIDDEN-CONTENT  [NEEDS REVIEW / Moderate]
    Found:   {Hidden sheet "{name}" / hidden rows {list} / hidden columns
             {list}} contain data.
    Action:  Confirm the hidden content is intentional, or unhide or
             delete it.                           Input: CHOICE
    Fix:     Right-click a sheet tab > Unhide; or select around the hidden
             rows/columns > right-click > Unhide.
  1.3.2-FLOATING-OBJECT  [NEEDS REVIEW / Moderate]
    Found:   {Text box/shape} "{name}" floats over {range} and contains
             text: "{first 50 characters}".
    Action:  Move the text into cells, or confirm it's not needed in
             reading order.                       Input: CONFIRM or EDIT
    Fix:     Copy the text into a cell, then select the shape > Delete.
  1.3.2-SHEET-ORDER  [NEEDS REVIEW / Minor]
    Found:   Sheet order: {list}. "{sheet}" (instructions/overview) isn't
             first.
    Action:  Confirm the order is logical, or reorder.  Input: CONFIRM
    Fix:     Drag sheet tabs into order.

  ===== 1.3.3 Sensory Characteristics (A) =====

  1.3.3-SENSORY-REFERENCE  [NEEDS REVIEW / Moderate]
    Found:   Text at {location} may rely on {color/position/shape}:
             "{matched text}".
    Action:  Confirm the instruction also names the cells or labels, or
             rewrite it.                          Input: CONFIRM or TEXT
    Fix:     Edit the text to add the reference (e.g. "fill in the yellow
             cells (column C)").

  ===== 1.4.1 Use of Color (A) =====

  1.4.1-CF-COLOR-ONLY  [NEEDS REVIEW / Serious]
    Found:   Conditional formatting rule "{rule description}" on {range}
             changes only {fill/font color}.
    Action:  Confirm the color carries meaning; if so, add a non-color cue
             (icon, bold, text label or status column).
                                                  Input: CONFIRM + EDIT
    Fix:     Home > Conditional Formatting > Manage Rules > Edit Rule >
             Format: add bold/italic or a number format; or add an Icon Set
             rule; or add a status column with text.
  1.4.1-MANUAL-COLOR  [NEEDS REVIEW / Moderate]
    Found:   Cells {range} in column {col} use a different
             {fill/font color} from the rest with no matching text marker.
    Action:  Confirm whether the color has meaning; if so, add a text
             equivalent.                          Input: CONFIRM + EDIT
    Fix:     Add a column with the status as text, or a symbol in the cell.
  1.4.1-CHART-COLOR-ONLY  [NEEDS REVIEW / Serious]
    Found:   Chart "{name}" has {n} series distinguished only by color
             (no markers, dash styles, patterns or data labels).
    Action:  Add a non-color cue.                 Input: EDIT
    Fix:     Select a series > Format Data Series > Marker (different
             shapes) or Line > Dash type; or Chart Design > Add Chart
             Element > Data Labels.
  1.4.1-LINK-COLOR-ONLY  [NEEDS REVIEW / Minor]
    Found:   Hyperlink at {cell} isn't underlined.
    Action:  Underline the link or confirm it's clearly a link another way.
                                                  Input: CONFIRM or EDIT
    Fix:     Select the cell > Home > Underline (Ctrl+U).

  ===== 1.4.3 Contrast (Minimum) (AA) =====

  1.4.3-TEXT-CONTRAST  [FAIL / Serious if < 3:1, otherwise Moderate]
    Found:   Contrast {ratio}:1 (font {color} on fill {color}, {size}pt
             {bold/regular}). Required: {4.5 or 3}:1.
    Action:  Change the font or fill color.       Input: EDIT
    Suggested: Nearest compliant font color: {hex}; or fill color: {hex}.
             (Compute by darkening/lightening along the same hue until the
             ratio is met.)
    Fix:     Select the cells > Home > Font Color / Fill Color > More
             Colors > enter the hex value.
  1.4.3-CF-CONTRAST  [FAIL / Serious]
    Found:   When conditional formatting rule "{rule}" applies to {range},
             contrast is {ratio}:1. Required: {threshold}:1.
    Action:  Change the rule's format colors.     Input: EDIT
    Fix:     Home > Conditional Formatting > Manage Rules > Edit Rule >
             Format.
  1.4.3-OBJECT-TEXT-CONTRAST  [FAIL / Serious]
    Found:   Text in {shape/chart element} "{name}" has contrast {ratio}:1.
    Action:  Change the text or fill color.       Input: EDIT
    Fix:     Select the shape/element > Shape Format > Text Fill / Shape
             Fill; or Format pane for chart elements.
  1.4.3-HIDDEN-TEXT  [NEEDS REVIEW / Moderate]
    Found:   Text at {range} is the same color as its background ("{first
             50 characters}").
    Action:  Confirm whether this hidden text is intentional. Screen readers
             still read it.                       Input: CHOICE
    Fix:     Change the font color, or delete the text if not needed.
  1.4.3-BACKGROUND-IMAGE  [NEEDS REVIEW / Moderate]
    Found:   Sheet "{sheet}" has a background image; text contrast can't be
             measured.
    Action:  Check text is readable, or remove the background.

------------------------------------------------------------------------------
8.7 Handling user responses
------------------------------------------------------------------------------
  - Fixed: The user changes the workbook in Excel and re-runs the
    validator. The finding should disappear; if not, it's still open.
  - Not an issue: The user dismisses the finding with a reason. Store it
    keyed by rule_id + location (plus a hash of the relevant content, e.g.
    the alt text) so it isn't reported again unless the content changes.
  - Values supplied in the report (TEXT inputs): Since the validator
    doesn't edit the file, these are a record for the person making the
    changes. If you later add an optional "apply fixes" feature, write to a
    new copy of the file and keep the original untouched.
  - Deferred: Keep the finding open and include it in the report summary as
    known outstanding work.
